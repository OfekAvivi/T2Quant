Precision matters at different denoising steps for different tasks: GSM8K in the first eight steps, HumanEval in the middle of the trajectory.

Signal

Where extra bits pay off is predictable without labels: quantization divergence times each window's influence on the rest of the generation.

01 · Overview

Precision as a resource spent over time

Diffusion Language Models (DLMs) introduce unique quantization challenges due to their iterative denoising process. In this work, we reveal that quantization sensitivity is both task- and time-dependent, with different downstream tasks exhibiting distinct precision requirements across denoising steps. We further show that these patterns can be predicted without ground-truth labels or task-specific evaluation metrics. Building on these findings, we introduce T²Quant, a task and time-aware mixed-precision quantization framework that uses a label-free sensitivity signal to optimally allocate activation precision across denoising steps under a fixed bit-width budget. Extensive experiments across three DLMs and six benchmarks demonstrate that T²Quant consistently improves the average accuracy of existing quantization methods, achieving gains of up to 6.7 percentage points under the same budget.

02 · Finding

When precision matters depends on the task

Uniform activation quantization treats every denoising step alike. Measured at the positions each window commits, the damage is concentrated, and it is concentrated in different places for different tasks.

Quantization divergence over the denoising trajectory
GSM8K HumanEval MMLU-Pro

KL(pfp ‖ pW4A4) at the score-relevant positions committed in each 8-step window, per committed position, normalized to each task's peak (256 calibration prompts; 50 on HumanEval; full-precision trajectory, W4A4 base). The paper's Figure 1 measures the same quantity along the W4A4 trajectory. Hover for values.

Time. A uniform spread would give each of the 16 windows 6.25% of the task-relevant divergence. Along the W4A4 trajectory of LLaDA-8B-Instruct, GSM8K's first window carries 27% (4.4× uniform) and its first quarter 55%. On HumanEval, five mid-trajectory windows (steps 32–71) carry 52%.

Task. GSM8K is strongly front-loaded. MMLU-Pro is early but broad: its first four windows are all within 10% of its peak. HumanEval is insensitive early and peaks broadly around steps 40–63. The profiles carry over to LLaDA-1.5 (per-window correlation 0.99, 0.98 and 0.92), so they survive preference alignment.

Key takeawaySensitivity varies across denoising steps, and the pattern differs by task. A single fixed temporal schedule is unlikely to suit every task.
03 · Method

Profile, score, allocate

T²Quant does not change the quantizer, the weights or the sampler. It only decides which activation width each denoising window runs at, and it needs a few unlabeled prompts from the task to do so.

Profile local divergence

Generate a full-precision reference trajectory per calibration prompt and replay each saved state at every candidate width b. Holding the state fixed isolates the local effect of precision.

κ_τ,k(b) = Σ KL(p_fp ‖ p_b) over committed positions in window k / number committed

Weight by influence

A window matters only if its commitments steer what comes after. Influence is how much they move the full-precision model's beliefs about the positions still masked.

ι_i,k = Σ over still-masked j of KL(p_fp(·|after) ‖ p_fp(·|before))
g_τ,k(b) = ῑ_τ,k [κ_τ,k(b0) − κ_τ,k(b)]

Allocate exactly

Pick one width per window to maximize the predicted gain at the uniform budget. A dynamic program over windows and cumulative cost finds the global optimum, and returns the uniform schedule when no trade pays.

b* = argmax Σ g_k(b_k) s.t. Σ c_k(b_k) = C0
F_k(z) = max_b { F_k−1(z − c_k(b)) + g_k(b) }

Why divergence times influence. For one window, let Jw be the KL between its commitments at the upscaled and target widths, and Rw the range of the expected final score over those commitments. The effect of upscaling the window obeys |ΔM_w|² ≤ ½ E[J_w] E[R_w²]. Neither term is observable on one unlabeled trajectory, so T²Quant uses the divergence Kw and the influence Iw as surrogates and ranks windows by S_w = E[K_w] E[I_w].

Divergence alone is not enough. On HumanEval it ranks the final window highest, although tokens committed last cannot affect anything after them. The influence weight removes such windows.

At inference the schedule is a 16-entry lookup indexed by the denoising step. There are no extra kernels and no per-token decisions.

06 · Ablations

Cheap to calibrate, stable, and about placement

LLaDA-8B-Instruct on GSM8K (512 held-out problems), shared W4A4 base, levels {3, 4, 8}. Uniform W4A4 scores 44.1, T²Quant 49.4 and FP16 52.9.

(a) Mean over three random subsets per size, with the range; 256 is the full pool. (b) The schedule calibrated at 4 tokens per step, reused unchanged. (c) The random control spends exactly T²Quant's bits, in shuffled windows. Accuracy in %.

16 prompts already recover about three quarters of the gain (48.0 against 49.4 with 256). Twelve random subsets of 16–128 prompts yield five distinct schedules, all the same shape: high precision early, low precision in the last four to eight windows.

The schedule transfers to 2 tokens per step with the same +5.3 points (60.5 against 55.3). At 8 tokens per step every row collapses (FP16 31.6) and the gain shrinks to a tie.

3.75 bits beat uniform 4 bits by 4.3 points, and bits beyond 4 buy nothing. The same bits in random windows stay at the level of uniform A3 (28.7): one early 3-bit window costs as much as making every window 3-bit.

07 · Use it

Run T²Quant on one GPU

The repository is a minimal, tested implementation for LLaDA-8B-Instruct: QuaRot-style rotation, GPTQ 4-bit weights, switchable per-token activation quantization, label-free calibration and the exact allocator.

  1. Install. Python 3.10+ and one CUDA GPU with 40 GB or more. The model and datasets download from the Hugging Face Hub on first use.

  2. Run the notebook. T2Quant.ipynb loads the full-precision reference and the quantized base, calibrates on 16 unlabeled GSM8K training questions, solves the allocation and evaluates FP, uniform W4A4 and T²Quant. It takes about 4–5 hours at the paper's setting.

  3. Scale out. The command line shards calibration and evaluation across GPUs and reports accuracy with 95% bootstrap intervals and an exact sign test.

git clone https://github.com/OfekAvivi/T2Quant.git
cd T2Quant
pip install -r requirements.txt
jupyter notebook T2Quant.ipynb   # or headless: python run.py
python -m pytest tests -q        # CPU tests, seconds
P="--task gsm8k --out runs/gsm8k --gen_len 512 --steps 128 --windows 16 --cache_dir cache"
for i in 0 1 2 3; do CUDA_VISIBLE_DEVICES=$i python -m t2quant.cli calibrate $P --shard $i/4 & done; wait
for c in fp uniform t2quant; do
  for i in 0 1 2 3; do CUDA_VISIBLE_DEVICES=$i python -m t2quant.cli evaluate $P --config $c --shard $i/4 & done; wait
done
python -m t2quant.cli report --out runs/gsm8k
